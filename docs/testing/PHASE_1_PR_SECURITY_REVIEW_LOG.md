# Phase 1 pull request security review log (internal engineering review)

**Status: internal engineering review by the implementing agent, 17 Nov 2026. It is NOT the independent security review required by Gate G1, it records no approval, and it does not certify any change for real data.** It exists so each pull request has a dated, reproducible record of what was probed, what was found and what was left open. Severity labels are the engineer's own. Results are for the exact heads named; they must be re-run after later changes. Local runs used Node 22 and PostgreSQL 16 on synthetic data; CI (Node 26.13.1, PostgreSQL 17) is reported separately.

## Method applied to every PR

1. Read the full diff against `main`; list every change to authorization, SQL, BFF routing, test data and dependencies.
2. Check for dependency, lockfile, workflow, container or environment-file changes (none in any PR below).
3. Scan added lines for credentials, tokens, private keys, connection strings, NIC-like and phone-like values (none found outside obvious synthetic test markers).
4. Run `pnpm audit --prod --audit-level low` and `pnpm audit --audit-level high` (no known vulnerabilities).
5. For code that changes authority: attack-style tests (bypass attempts, not only happy paths) and **mutation checks** that the security assertion fails when the control is removed.
6. For designs: a threat pass (STRIDE style) with binding requirements written back into the design.
