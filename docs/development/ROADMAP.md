## Next state-management work at M2

1. Extend [the implemented TanStack Query admin read boundaries](PROTECTED_ONLINE_QUERIES.md) to field/other online domain reads/mutations with the typed BFF transport. Use structured domain/filter/page keys bound to current authorization context; avoid dual server-record ownership in component state or Zustand.
2. Prove logout/session/account/device/scope transition cancellation and cache clearing, including late responses. Preserve current no-store server responses and denied-read behavior. Never infer permission from a cached record or capability.
3. Introduce a small shared Zustand locale/preferences store when coordinating the existing bilingual views. Persist only approved non-sensitive preferences, keep local forms local, and use URLs for shareable filters where suitable.
4. Keep Dexie as the durable pending-work owner. Online mutation status/invalidation must not create a second queue or replace stable entity/mutation IDs. Preserve encrypted legacy drafts, recovery versions and interruption/idempotency behavior during integration.
5. Preserve [the implemented transient per-mutation Syncing presentation and tested interruption/retry behavior](FIELD_SESSION_SYNC.md). Extend land/GPS offline data only after the minimal-data/device policy is reviewed; selection of Dexie alone grants no additional storage permission.

## Conditional Redis work at M3+

Keep registration and session/permission authority on PostgreSQL. Introduce Redis only against a confirmed reference/configuration cache, aggregate, rate-limit or worker requirement and measurements. Document scope/version keys, TTLs/invalidation, ordinary-cache database fallback and security-critical failure policy. Test Redis unavailability for that implemented use case. A future worker relay must start with atomically committed PostgreSQL business-event outbox records; the existing mutation journals do not supply that relay.

No new library, Redis service, query persister or offline queue is installed by this roadmap. Track implementation in the existing [remaining-engineering-work backlog](PHASE_1_STATUS.md#remaining-engineering-work), update status as code/tests land, and propose an updated ADR when requirements conflict.
