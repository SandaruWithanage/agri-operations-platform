# Protected online query integration

Read the [accepted data/state/cache ADR](../architecture/decisions/ADR-data-state-cache.md). This is the incremental TanStack Query integration for admin farmer registry, detail, audit-history and land directory reads. The [field home session display](FIELD_SESSION_SYNC.md) also uses isolated queries; future online domain mutations still need integration. PostgreSQL remains authoritative, and cached capabilities never confer permission.

## Implemented boundary

The admin app pins `@tanstack/react-query` to 5.90.21. Each mounted registry owns an in-memory QueryClient; audit history has a separate short-lived boundary. Changing transport replaces the registry boundary. Refreshing context or changing account, device, view or page clears the previous registry query; changing account, farmer or authorization epoch replaces history. Logout, hidden-view clearing and failed requests clear protected records and unmount history. Cleanup cancels outstanding work and clears the cache. No shared server singleton, dehydration, query persister, localStorage/IndexedDB record cache or query mutation queue is used.

Keys include the protected domain, account and relevant device, local authorization epoch, view/filter/page identity and bounded page size. History includes the exact microsecond cursor and explicit read revision. The epoch is a local lifecycle counter, not a session credential or caller-selected backend scope. Responses must match the expected account, and detail/history must match the requested farmer, before entering the cache. Each explicit page/latest action has a new read revision and rechecks server authority; previous-page snapshots are not displayed while a new request is pending or denied. The previous unobserved query is immediately eligible for collection.

Queries have zero stale time and zero inactive retention, no automatic retries, and no focus/reconnect refetch. Online reads use `networkMode: always`: unavailable connectivity returns a visible failure rather than pausing a hidden request for later. This deliberately favors a fresh authorized read over page-cache reuse while a server-issued permission-context version is unavailable. These settings are not a blanket policy for future public/reference queries.

TanStack Query owns farmer/land registry/detail and farmer history records and their loading/error state. Component state contains view/cursor choices, history visibility and non-sensitive authentication lifecycle metadata (account/device IDs only); authorized geography arrays and farmer records are not copied into it. Session discovery remains an explicit cancellable authentication bootstrap. Login credentials remain in the form/request, and a late login or session response after view clearing cannot restart a private read. The typed BFF transport combines query cancellation with its existing 15-second timeout. The query function consumes the cancellation signal and checks it again before returning; an adapter that resolves late cannot restore cleared data. The browser receives no JWT or session secret.

## Incremental migration and limits

Continue with field online references/mutations and new domain views, using tested account/session/device/scope boundaries rather than extending a shared unscoped cache. The current history boundary observes explicit parent lifecycle changes; it does not receive push notifications of server-side permission revocation. Each read remains checked by NestJS and database ABAC/RLS, and denial clears the protected parent view. A future server authorization-context revision or push/poll protocol needs its own contract and tests.

Dexie continues to own encrypted durable drafts and stable mutation IDs. No existing outbox format, pending registration, archive/recovery behavior or minimal farmer-only storage policy is changed. Zustand now provides the [shared locale preference](SHARED_LOCALE.md) only, and Redis remains absent and conditional on a confirmed need.

Run the normal installation/format/lint/typecheck/unit/integration/build/browser checks. Component tests cover account, transport and same-account epoch transitions, exact cursors, denied reloads, logout/hidden-view cleanup, cleared caches, late responses, cancellation reaching fetch and React strict lifecycle replay. Existing live PostgreSQL/BFF tests establish current authority; browser adapters alone do not establish security or production readiness.
