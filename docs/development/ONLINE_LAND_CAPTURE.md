# Online reported land capture

After sign-in, choose **Reported land → Record land identification**. Use the existing [pilot runtime setup](PILOT_AUTH_RUNTIME.md), native migration manifest through entry 18 and ninth restricted land database login described in [land API setup](LAND_IDENTIFICATION.md). This form adds no migration, default grant or environment setting. HTTPS, an approved account/device and current administrator-source `land.create` coverage are required. Farmer permissions and land-read permissions are independent.

Select a configured authorized location. Optionally enter a label, latitude/longitude pair, reported accuracy in metres and reported hectares (up to four decimal places). GPS, area and label are never mandatory. Accuracy requires a point. Values are checked in the form, NestJS and database; coordinates/accuracy/area may be zero. Points are WGS84 identification data, not surveyed polygons. The selected geography is an authorization scope, not verified spatial containment.

**Use current GPS location** explicitly requests browser location permission with high accuracy, no cached position and a ten-second timeout. A denied/unavailable location does not prevent registration without a point. Cancel an outstanding request or enter values manually. Editing or locking the form invalidates late GPS callbacks. No area is calculated and no third-party map service is contacted.

The form supports English/Sinhala switching and uses the shared administrator online-creation controls: one open draft, five-minute inactivity locking, hidden/navigation/logout/transport/denial locking, original-account/device access checks and exact idempotent retry. A submitted request is fixed. An uncertain response requires an explicit retry with the same IDs; reconnection does not submit automatically. A conflict preserves values for review. Discard requires identity checking and confirmation and cannot undo a server commit.

Successful registration refreshes the land directory with current read permissions. A create-only user can register without seeing the result. Creating land establishes no farmer, ownership, officer or project relationship, and no verified acreage or legal boundaries.

**This form is online and tab-only.** Keep it open until acknowledgement; tab/browser termination may lose unsent values and request IDs despite the leave-page warning. No land/GPS dataset is added to the field Dexie outbox, public cache or browser persistence. Offline GPS, map/search, configurable farmer relationships, durable online recovery and real-device/native-speaker acceptance remain follow-up work. See [ADR 0015](../decisions/ADR-0015-online-land-capture.md) and [test evidence](../testing/ONLINE_LAND_CAPTURE_RESULTS.md).

For development use synthetic data and the normal install, peer/audit, lint, formatting, type-check, disposable PostgreSQL/PostGIS tests, production builds and Chromium checks. `PilotClient.registerLand(accountId, input, expectedDeviceId?)` binds retained requests to their original device; `landGeographies(signal?)` supports cancelled protected reads. The optional parameters preserve existing callers while the online adapter always supplies both bindings.
