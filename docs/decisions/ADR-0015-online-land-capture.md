# ADR 0015 — Online reported land capture

Status: implemented technical workflow for the provisional pilot, supplementing ADR 0011 and ADR 0014. Legal tenure, farmer/land cardinality, official boundary datasets, offline GPS storage, map hosting and client/device acceptance remain unresolved.

The admin application exposes the existing land-identification service through an online bilingual form. Configured geography is required; label, point, reported accuracy and reported hectares are optional. Both coordinates are required when reporting a point. Accuracy cannot exist without a point. Zero values remain valid. Numeric/range/precision checks use the existing strict shared contract and native database constraints.

GPS is requested only after the user selects **Use current GPS location**, in a secure context, with a fresh high-accuracy request and a ten-second timeout. The browser controls location permission. A denied/unavailable/invalid result allows retry, manual point entry or registration without a point. Cancellation, manual edits, hiding, protected locking and unmounting invalidate late GPS results. No continuous tracking, map provider, area calculation or legal verification is added. Reported location does not prove containment in the selected configured geography.

PostgreSQL/PostGIS retains authority. The existing administrator BFF source, current session, CSRF, NestJS checks, `land.create` coverage, native idempotency journal and atomic audit govern every submission. `farmer.create` grants no land authority; `land.create` grants no read authority or farmer/project association. Device identity is checked around creation-reference reads and bound to each retained submission before POST. API/database permission checks remain mandatory regardless of cached choices.

The administrator farmer-registration and land-capture adapters share the tested online-creation controls. TanStack Query owns current creation references and mutation status. Local component memory owns working fields and one immutable submitted request. Only one farmer registration, correction or land draft can be open. Protected transitions cancel/clear fetched state and hide values; reopening requires original account/device and current selected-location coverage. A late acknowledgement cannot consume a locked draft. Exact retry uses the original entity/mutation IDs; reconnect never submits automatically. Conflicts never overwrite data.

Success clears the draft and refreshes the land directory under current read permissions. It never displays submitted coordinates as a substitute for an authorized read. Explicit identity-bound discard warns that it cannot cancel an accepted or running server request.

Land/GPS values are not saved to IndexedDB, localStorage, URLs, Zustand or public HTTP caches. The minimal farmer-only encrypted field outbox remains unchanged. Tab crash/reload can lose unsent values and retained IDs; the notice and leave-page guard are not durable recovery. Investigate uncertain outcomes through an authorized administrator before recording another submission. Expanded offline land storage requires separate device/data-security and recovery validation, as required by the accepted architecture.
