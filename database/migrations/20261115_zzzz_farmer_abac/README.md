# Minimal farmer ABAC/RLS proof (provisional)

Apply transactionally after the authentication migrations in a disposable database. It creates configurable organizations, units, geography, scoped permissions and assignments, plus a minimal farmer table and registration audit. PostgreSQL row-level security is forced for the NOLOGIN `agri_farmer_runtime` role. There are no update/delete grants or policies, and sensitive optional fields, fuzzy duplicate matching, full device sync and general administration are not implemented.

Actor context consists of account UUID, session UUID and an HMAC bound to PostgreSQL's transaction ID. Provision the same random key (at least 32 bytes) separately to the trusted API and to `authz.context_key` using a privileged provisioning process; never put it in a migration or repository. A missing key or invalid context denies access. The runtime role cannot read the key or set the NOLOGIN policy-owner role. The caller must derive actor and session IDs from verified server-side authentication; the HMAC is not a substitute for authentication.

The database checks and locks current session, account and optional device state. It locks matching permissions and assignments and evaluates all constraints within each grant as an intersection. The hierarchy is locked in SHARE mode while scopes are evaluated; this is intentionally conservative and may limit administrative throughput. Unit ancestry is data-driven and cycles fail closed. Create permission does not imply read permission, and the registering officer is not automatically assigned ongoing access. Registration events are inserted by a restricted trigger in the same transaction.

The policy owner is NOLOGIN and has limited table privileges needed for row/table locks, signing-key access and audit insertion. Runtime must never be a superuser, table owner or BYPASSRLS role. Provision roles, key rotation, trusted connection management, concurrent revocation tests, security review and performance testing before pilot usage. MFA and session issuance must be integrated first. Do not treat this proof as a complete authorization system.

Registration is available only through `farm.register_farmer`: direct runtime INSERT is revoked. The function rechecks creation authorization, records a payload MAC and mutation ID atomically, rejects changed-payload retries, and returns the original result for an authorized replay. Replays recheck current permission. A provisional exact-name/geography duplicate risk is recorded privately for review; records are never automatically merged and the caller receives no other farmer details. Registrations are serialized per geography for this risk check. Sensitive optional fields, review workflows and production performance testing remain unfinished.
