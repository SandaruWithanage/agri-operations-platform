# Transactional session use and logout (provisional)

Apply `up.sql` only after the authentication foundation, using an audited privileged migration identity in a disposable development database. Apply the entire migration in one transaction so function creation, ownership and PUBLIC privilege revocation become visible together. It creates NOLOGIN roles and grants only function execution to `agri_session_executor`; provision any dedicated login separately without BYPASSRLS or superuser privilege. No credentials are included. Function ownership is assigned to a separate NOLOGIN role with only the privileges needed for session/account/device row locks and updates. `PUBLIC` cannot execute the functions.

`authn.use_session` accepts a SHA-256 cookie-secret digest and a bounded idle interval, locks the session, account and optional device rows, fails closed on revocation or expiry, and caps idle renewal at the absolute expiry. `authn.logout_session` revokes the session and inserts its audit event atomically. Callers must still enforce CSRF for cookie-authenticated state changes and protect cookie secrets; no endpoint is wired. For operations that depend on current session status, keep the session check and protected database action in the same transaction; a pool query that commits before the action does not prevent revocation races. Account/device revocation, MFA, authentication, registration ABAC/RLS, production ownership review and operational deployment are not implemented by these functions.

Lock ordering is session, account, then device. Future revocation workflows must use compatible ordering or handle transaction retries after database deadlock detection. Use only synthetic data for verification. Do not remove tables or roles as routine rollback; use a reviewed forward fix and recovery plan.
